# Codec Panel 1.0.6 安定版の使い方

開発・配布：月澄（つきと）

本アプリは、生成AIとの対話を通じて、設計・コード作成・修正を進める「バイブコーディング」で開発しています。

## インストール

1. [正規の配布元のGitHub Releases](https://github.com/tsuki-to-082/CodecPanel/releases)を開きます。
2. Assetsから `CodecPanel-1.0.6-release.apk` をダウンロードします。
3. ダウンロードしたAPKを開きます。Androidから求められた場合は、そのブラウザーやファイルアプリからの「不明なアプリのインストール」を許可します。
4. Androidのインストール画面を確認し、インストールします。

対象はAndroid 12以降です。GitHubが用意する `Source code` のZIPや、この配布セット全体のZIPはAPKではありません。

## Bluetooth機器と接続する

1. AndroidのBluetooth設定でイヤホン・ヘッドホン・Bluetooth DACなどを音楽用に接続します。
2. Codec Panelを開き、Bluetoothの許可を与えます。
3. アプリの **設定 → 接続 → 接続方法** を開き、接続方式を設定します。
4. Shizuku方式を使う場合は、**接続のヘルプ** に従って起動と許可を完了します。

Shizukuは別のアプリです。[公式ダウンロード](https://shizuku.rikka.app/download/)と[公式の起動手順](https://shizuku.rikka.app/guide/setup/)も参照できます。ワイヤレスデバッグで開始したShizukuは、スマホの再起動後に起動し直します。

機器登録方式は、Shizukuを使わない試験機能です。利用できるかどうかは端末とAndroidの版によって異なります。本アプリのコーデック設定は音楽用Bluetooth接続（A2DP）が対象です。

複数の音楽用機器が接続されている場合は、**機器を選ぶ** で対象を選択します。

## コーデックと伝送設定

**利用可能なコーデック** から、接続先とAndroidが対応するコーデックを選択します。変更後は、Androidから読み直した現在の設定を確認します。

**伝送設定** では、対応する値だけ選べます。

| 項目 | 選択内容 |
| --- | --- |
| サンプルレート | 自動、または接続で対応するkHzの値 |
| ビット深度 | 自動、または接続で対応する16／24／32 bit |
| LDAC通信品質 | 自動／音質優先／バランス／接続優先 |

ビットレートの手動選択はLDACの品質設定に対応します。表示するビットレートは目標値で、実測した速度ではありません。

伝送設定の右上の **リセット** は、現在のコーデックを保ち、サンプルレート・ビット深度と、対応するLDAC品質を自動選択へ戻します。自動で選ばれる値はAndroidと接続機器によって異なります。

コーデックや伝送設定の変更後は、機器側の表示更新を補助するために短い無音データを送信します。音楽再生中・通話中は省略し、端末の音量は変更しません。この動作を切り替える設定項目はありません。

## バッテリーと表示

残量を取得できる機器ではバッテリーを表示します。設定の「左右・ケースの残量」スイッチで、左右・ケースの表示をオン／オフできます。左右・ケースの情報が取得できる場合は個別に表示します。機器が報告しない値は推定せず、未取得の表示にします。

- 11〜20%：黄色
- 0〜10%：赤色

設定の「ダークモード」スイッチで黒背景／白背景を切り替えられます。アプリアイコンは **設定 → 表示 → アプリアイコン** をタップし、一覧から選べます。起動アニメーションは約2秒で、新しいタスクとして起動したときに再生します。ホームからの復帰では繰り返しません。

## 再生中の曲を表示する

設定 → 再生中のメディア → **曲情報・再生操作** をオンにし、**通知へのアクセスを設定** からAndroidでCodec Panelを許可します。初期状態ではオフです。

音楽アプリで曲を再生すると、曲名・アーティスト・アルバム画像をアプリとウィジェットに表示します。画像や操作の対応状況は再生アプリによって異なります。曲表示は端末内の再生情報で、Bluetooth機器の伝送設定とは別の情報です。

アプリ内の「再生中のメディア」の下部に、前の曲・再生／一時停止・次の曲のボタンを表示します。再生アプリが対応している操作だけが有効になります。ボタンの表示は、再生アプリから受け取った実際の再生状態に従います。

## 再生位置のデザインを選ぶ

設定 → 表示 → **再生位置のデザイン** をタップし、一覧からA（ライン）・B（ドット）・C（ジャケット外周）を選びます。初期設定はAです。アプリ内とウィジェットに共通で反映し、選択は保存されます。

再生位置・経過時間・曲の長さは、再生アプリが提供する情報を使います。一時停止中は表示も止まります。曲の長さや位置が分からない場合は進行率を表示せず、Cでジャケットがない場合はラインで表示します。小型のウィジェットでは、空間に合わせて再生位置を省略します。

この表示は、曲のどの部分を再生しているかを見るためのものです。バーをドラッグ・タップして再生位置を変更する機能はありません。

## 通知アクセスを許可できない場合

Android 13以降などでは、インストール方法によって「制限付き設定」の案内が表示される場合があります。曲情報の表示を使う場合は、配布元と権限の用途を確認し、Androidのアプリ情報 → Codec Panel → 右上メニューの「制限付き設定を許可」など、端末側の案内に従ってから通知アクセスの設定へ戻ります。項目名や利用できる操作は端末によって異なります。

[Android公式の説明](https://support.google.com/android/answer/12623953?hl=ja)を確認してください。曲情報を使わない場合は、通知アクセスを許可する必要はありません。

## ウィジェットを追加する

ホーム画面を長押しし、ウィジェット一覧からCodec Panelを追加します。横長4列×2行を目安に配置でき、縦横にリサイズできます。配置できる大きさはホームアプリによって異なります。

横長では左に角丸のジャケット、右に曲名・アーティストと再生操作、下段に大きなコーデック名・サンプルレート・ビット深度・機器名と全体残量を表示します。小さいサイズでは表示項目を絞ります。

右上のアプリアイコンを押すとBluetooth情報と曲情報を更新します。アイコンや操作ボタン以外を押すとCodec Panelを開きます。接続状態の通知やAndroidの定期更新でも情報を読み直します。ホームアプリや省電力設定により更新が遅れる場合があります。

曲情報をオンにすると、対応する再生アプリに対して **前の曲・再生／一時停止・次の曲** を操作できます。対応しない操作は無効になります。前の曲の操作で曲の先頭へ戻るか、前の曲へ移るかは再生アプリの動作に従います。

未接続のときは、下段に4つの点（右端だけ赤）と **DISCONNECTED** を表示します。機器への接続を確認すると **CONNECTED** を約2秒表示し、その後は機器名と取得できる残量に切り替わります。同じ機器の情報更新では、この表示を繰り返しません。Bluetooth情報を確認できない状態は、未接続と断定せず確認が必要な表示にします。

## 不具合を報告する

**設定 → サポート → バグ報告を作成** で入力し、プレビューを確認します。**報告内容をコピー** で報告文をコピーします。次に **フォームを開く** で[作者のGoogleフォーム](https://forms.gle/GGoeg9g6n83f7d4v5)を開きます。フォームを開いてもクリップボードの内容は変更しません。

最初に **バグ報告** を選び、**報告内容** に貼り付け、必要なら **備考** を追記し、フォームで送信してください。コピーとフォームを開く操作だけでは送信は完了していません。

診断情報の添付と返信用メールアドレスの記入は任意です。返信用メールアドレスは、その報告または問い合わせへの返信のみに使用します。

## お問い合わせ

**設定 → サポート → お問い合わせを作成** で種類・件名・内容を入力します。件名と端末情報の添付は任意です。プレビューを確認し、**問い合わせ内容をコピー** を押します。

**フォームを開く** で[作者のGoogleフォーム](https://forms.gle/GGoeg9g6n83f7d4v5)へ進み、最初に **お問い合わせ・ご要望** を選びます。**お問い合わせ内容** に貼り付け、返信を希望する場合のみ **返信用メールアドレス（お問い合わせ）** を記入して送信してください。コピーとフォームを開く操作は独立しており、アプリから自動送信しません。

フォームの利用にはGoogleへのログインが必要です。パスワードや不要な個人情報は記入しないでください。

## 更新

新しい安定版が公開されると、アプリを開いたときにコーデック画面へお知らせを表示します。自動確認は初期状態でオンで、1日1回までです。アプリを閉じている間は定期確認しません。ベータ版は案内の対象に含めません。

**設定 → アプリの更新 → 更新を確認** で公開状況を手動確認できます。同じ画面の「更新を自動で確認」スイッチでオン／オフを切り替えられます。「あとで」で閉じたお知らせは、さらに新しい安定版が出るか、手動で確認するまで表示しません。

新しい安定版のお知らせの **ダウンロード**、または設定の **更新とAPKの整理** で、更新画面を開きます。新しい安定版に対応するAPKがある場合は、次の手順で更新できます。

1. **安定版のAPKをダウンロード** を押します。モバイル回線も使用します。
2. ダウンロード完了と、ファイル・アプリ・署名・版の確認を待ちます。
3. **Androidの更新画面を開く** を押します。初回はAndroidの案内に従い、Codec Panelからのインストールを許可します。戻ったらもう一度同じボタンを押します。
4. Androidのインストール画面で **更新** を選びます。アプリは自動でインストールしません。
5. 更新後にCodec Panelを起動すると、アプリ内でダウンロードした不要な更新用APKを削除します。更新を中止した場合は保持し、**保存したAPKを削除** で削除できます。

ベータ版、およびアプリ内ダウンロードに対応したAPKがない版は、**GitHubの配布ページを開く** から手動で更新します。Assetsから公開用APKを開き、Androidの画面で **更新** を選んでください。アンインストールは不要です。

1.0.0-beta.1には更新のお知らせ機能がないため、1.0.6へは手動で更新してください。同じ公開用アプリIDと署名で、版番号を増やしたAPKを使用すると、設定を保ったまま更新できます。

## スマホに残った古いAPK

ブラウザやGitHubアプリから保存したAPKは、Codec Panelによる自動削除の対象ではありません。更新後、端末のファイルアプリの **ダウンロード** から不要なCodec PanelのAPKを削除してください。設定の **更新とAPKの整理 → ダウンロード一覧を開く** から開ける場合もあります。

APKはインストール用ファイルです。削除しても、インストール済みアプリや設定は消えません。自動削除で扱うのはCodec Panel自身が管理する更新用APKだけです。

## パッチノートを読む

この版を初めて開くと、コーデック画面に変更点の案内を表示します。**パッチノートを見る** で現在の版と過去の配布版の変更点を読めます。**閉じる** または閲覧後は、同じ版の案内を繰り返しません。**設定 → パッチノート** からいつでも読み直せます。アプリ内の履歴は通信せずに表示します。

安定版の更新案内の **更新内容を見る** は、その安定版のGitHubリリースをブラウザーで開きます。各ベータ版の説明と履歴も、パッチノート画面の **GitHubのパッチノートを開く** から確認できます。

## Android 12・13の接続確認

一部端末のBluetoothサービスAPIに合わせた互換対応を追加しています。機器登録接続で機器・現在のコーデック・利用可能な候補が表示されるか確認してください。OSが権限エラーを返す場合は、設定からShizuku接続でも確認できます。
